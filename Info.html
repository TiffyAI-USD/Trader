THE TIFFY MESH ARCHITECTURE

Decentralized Web Stores, Peer State Bridging, and Autonomous Commerce

Modern web development often chains creators to centralized servers, restrictive databases, and rigid cloud monopolies. But what if a web store could exist entirely as an autonomous, self-contained HTML artifact, routed and synchronized through a decentralized browser mesh?

This is the core philosophy behind the Tiffy Architecture—a system engineered to put total sovereign control back into the hands of creators, developers, and marketplace operators.

1. The MESH_DIR Protocol & IndexedDB Persistence

At the heart of the system is MESH_DIR, a structured dictionary object stored locally via browser IndexedDB. Instead of relying on a distant backend SQL server to map applications, the terminal treats the browser itself as a node server.

  • Peer ID Mapping: Every deployed store is indexed directly by its unique Peer ID.
  • Isolated Payloads: Each store record encapsulates its full raw HTML, base64 thumbnail assets, customer review arrays, and real-time synchronization timestamps.
  • Zero-Loss Merging: Using deep object combination logic, subsequent browser uploads merge seamlessly—preventing data collisions and ensuring historical store nodes are never overwritten.

2. Cross-Browser State Bridging

Decentralization requires fluid movement between environments. Rather than depending on live websocket handshakes that can fail behind restrictive firewalls, the Tiffy bridge utilizes State Export and Stable File Merging.

How it works: Browser 1 exports its cumulative multi-store ledger into a portable .json state file. When imported into Browser 2, the mesh bridge reads the local database, compares keys, and aggregates all unique peer nodes together—creating an instantly synchronized, multi-browser ecosystem.

3. Marketplace Partition Rooms

To scale beyond a single directory, the system partitions commerce into dedicated category rooms such as MESH_DIR_CLASSIFIEDS, MESH_DIR_JOBS, MESH_DIR_SOFTWARE, and MESH_DIR_RESTAURANTS. Each category acts as an independent room on the mesh network, populated by starter stores and expandable via peer-to-peer file merging.

4. The Road Ahead: Sovereign Creator Revenue

As the network matures, the next frontier focuses on monetization. By embedding verifiable sales logging directly into the immutable runtime of each store's HTML package, creators will soon be able to inspect performance locally and claim their revenue transparently—bridging the gap between decentralized deployment and autonomous creator compensation.
